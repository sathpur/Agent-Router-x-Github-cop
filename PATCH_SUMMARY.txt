PATCH 1: Allow custom User-Agent header
----------------------------------------
LOCATION: Sl class _reservedHeaders Set
FUNCTION: _isReservedHeader() / _sanitizeCustomHeaders()

WHAT WAS CHANGED:
  - Removed "user-agent" from the _reservedHeaders Set
  - This Set defines headers that Copilot Chat will NEVER send, even if provided in requestHeaders
  - By removing "user-agent", custom User-Agent headers from chatLanguageModels.json can now reach AgentRouter

WHY NEEDED:
  - AgentRouter rejects requests with "unauthorized client detected" unless a specific User-Agent is sent
  - Copilot Chat was blocking the custom User-Agent before it left the extension
  - Even though requestHeaders contained User-Agent, it was silently dropped

BEFORE:
  this._reservedHeaders = new Set([
    "accept-charset", "accept-encoding", ..., "user-agent", ...
  ])

AFTER:
  this._reservedHeaders = new Set([
    "accept-charset", "accept-encoding", ..., (user-agent removed) ...
  ])

RESULT: Custom User-Agent header now flows through to AgentRouter requests

PATCH 2: Fix null usage crash in SSE streaming
----------------------------------------
LOCATION: processSSEInner() function
FUNCTION: Handles streaming response chunks from the API

WHAT WAS CHANGED:
  - Added null/object type check after JSON.parse(d)
  - The code assumed parsed JSON was always an object
  - Now it skips malformed/null chunks instead of crashing

WHY NEEDED:
  - Some API responses contain empty or non-object JSON chunks
  - This caused: TypeError: Cannot read properties of null (reading 'usage')
  - The crash aborted the entire stream and broke the chat response

BEFORE:
  let p;
  try { p = JSON.parse(d) }
  catch { ...; continue; }
  if (p.usage && ...) { yield p.usage }

AFTER:
  let p;
  try { p = JSON.parse(d) }
  catch { ...; continue; }
  if (!p || typeof p !== "object") continue;
  if (p.usage && ...) { yield p.usage }

RESULT: Malformed SSE chunks are skipped gracefully, no more null reference crashes
